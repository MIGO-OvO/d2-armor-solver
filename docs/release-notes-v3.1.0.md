# v3.1.0

V3.1.0 是把 develop 上这一轮开发整体推进到稳定通道的正式版本，包含 `main..develop` 的 31 个提交。这一轮的主线有两件事：**V3 求解器的搜索与证明语义按真实库存场景收敛**，以及**结果工作区按「一个信息只出现一次」的原则重建**。

求解器侧，V3.1 在不改变游戏规则与见证/证书信任边界的前提下，显著加快了精确目标与库存搜索；界面上，结果页从「逐个卡片堆叠」变成「列表 + 详情」的两栏工作区，库存证明与全局搜索状态被彻底分开。同时补上了三语独立使用说明、保存方案的跨渠道保活，以及一批真实 DIM 库存下的正确性回归。

## 求解器 / V3.1 算法与性能

- **精确目标原像查询**：可见值 0/200 这类被界面钳制的目标，现在直接用完整的六维护甲区间去查询既有的规则区间 Oracle，而不是只枚举 8/128 个原像点。部分固定件的精确查询同样接受六维区间：先按物理上下界与守恒总量收紧，再剪枝配置树，最后在一个有界的调整晶格盒或可达向量集合里自适应探测。
- **混合调整模式的残差预筛**：从零求解在构造笛卡尔积之前，先按目标残差过滤 Balanced 候选；存活的候选保持既有 canonical 顺序与原型代表，部分固定配置的点查询复用同一必要条件。存在性流在拿到见证配额后即停止。
- **调整 DP 与缓存**：调整 DP 改用整数键；无限制的能力模式复用有界稠密缓存，而不是再构造一份稀疏索引。诊断计数器可以直接读出构建耗时、缓存命中与未命中。
- **搜索剖面被真正尊重**：Fast / Balanced 的预算不再被上层包装覆盖。
- **性能结果**（1300 件合成库存，同一台 Windows 主机，每个版本/用例三次冷进程运行的中位数）：

  | 用例 / 指标 | 基线中位数 | 优化后中位数 |
  | --- | ---: | ---: |
  | 库存硬规则，首个可行解 | 1610.8 ms | 145.3 ms |
  | 库存硬规则，总搜索时间 | 3000.5 ms | 3000.9 ms |
  | 库存 late exact，总搜索时间 | 544.5 ms | 545.1 ms |
  | 从零求解 混合 +3=2，精确 Oracle | 593.0 ms | 66.1 ms |
  | 从零求解 混合 +3=3，精确 Oracle | 539.7 ms | 39.1 ms |

  在同样的目标下，从零求解的配对访问次数从 23,049,601 降到 117,601 / 21,169，见证结果保持 86 / 32 不变。库存侧的精确重建状态全部保持。
- **可取消的构建**：固定目标、固定规则、固定排序与残差索引的构建循环都接受取消/时间检查点，被打断的构建永不写入缓存。「优化现有配装」在进入可取消的重分配之前，会先发布一份已验证的手工基线，冷取消不会再返回空白界面。
- 算法细节与完整测量记录见 [`docs/solver-v31-optimization.md`](./solver-v31-optimization.md) 与 [`docs/benchmarks/solver-v31.json`](./benchmarks/solver-v31.json)。

## 搜索状态、证明语义与结果正确性

- **库存证明与全局搜索状态彻底分离**：过去两者共用一个状态位，导致「理论求解已完成、库存侧仍在搜索」时状态显示混乱。现在库存证明独立于完成度、搜索上限与取消状态，各自如实陈述。
- **取消的可达性探测不再被当成失败**：用户主动取消或预算切换导致的探测中断，不再显示为错误。
- **搜索状态文案回归语义**：`EXACT_TARGET_PROVEN` / `RULE_FEASIBLE_PROVEN` / `INFEASIBLE_PROVEN` / `SEARCH_LIMIT_REACHED` 的含义不变；预算是预算，不是不可行证明。
- **规则集 id 记忆化**：`createRulesetId()` 的 canonical 序列化按输入对象身份做 WeakMap 记忆化。证书与证明投影每次都会重算该 id，并行客户端还会对每个保留行重复计算，这一改动去掉了一处隐藏的毫秒级热点。
- **三层等价键**：护甲能力现在显式暴露 `mathEquivalenceKey`（只影响数学结果的量）、`executionEquivalenceKey`（能量、插槽、调整可执行性、可穿戴性）与 `physicalIdentity`（实例 id / hash / 持有者 / 是否穿戴）。搜索可以共享数学、但必须独立保留与验证每一个物理实例。
- **固定异域是约束而不是事后匹配**：固定普通异域现在进入搜索约束本身，而不是先搜再过滤。

## mathematical / projected / execution totals

这是本版最重要的一处正确性修复：过去「方案数学上达到的六维」和「执行后真实得到的六维」会在同一个数字里混杂。

- **mathematical**：方案在数学上达到的六维，包含全部计划的调整、模组、满级与碎片效果。**结果页主六维条只显示这一层**，达标判定来自同一域的证书。
- **projected**：`assignArmorMods()` 的投影结果加碎片，是执行层与求解器之间唯一的一致性桥梁。
- **installable**：执行后真实可安装的状态。每一件使用「已落定则用期望值、否则沿用当前实际模组」的语义；被证明不可能写入的模组不会反过来改动玩家原有的 modifier。
- **求解器的数学总量不再混入 installable 子集**：`installableTotals` 只作为执行预检辅助，出现在「高级诊断」折叠区与执行提示里，不再反向覆盖主六维。
- **受阻写入保留已安装模组**：当一处计划写入被证明受阻时，执行层保留该件上原有的 modifier，而不是把它清空。

## DIM 库存与真实护甲

新增真实 DIM 导出回归（`tests/dim-inventory-regression.test.mjs`，含 `dim-mask-of-fealty.json` fixture），覆盖：

- **同一份上报库存恢复出两份物理精确配装**，且不修改 CSV 里已安装的模组。
- **库存自动属性模组与 CSV 已安装件数解耦**：库存自动模组的可用性独立于 CSV 记录的已安装数量。
- **显式预算优先于已安装模组**，并保留用户请求的 Balanced 数量。
- **零已安装模组的大库存不会被「已安装预算」上界剪掉**。
- **并行库存求解**：DFS 分片按物理候选切分（包含当前配装本身），分片进度在兄弟分片完成前就能发布已验证见证，也能在中断后保留；新批次取代旧批次，普通请求取代批次请求。分片结果在未完成时保持「不完整」标记，不会再被当成穷尽结论。
- **修复 develop 上的库存搜索与 Worker 生命周期**，恢复并行结果比较器的稳定性。

## Unified Plan 与结果工作区

- **方案列表合一并优先排序**：从零求解与优化现有配装的结果合入同一列表，按「先达标、再拥有度」的稳定分区排序；规则达标但无法映射到具体件（例如缺少可执行实例）的理论方案不会被误判为达标。
- **统一去重键**区分「已拥有的实例」与「待刷取的空缺」，同一件护甲的不同实例不会被合并。
- **唯一取参入口**：Save / DIM 导出 / Bungie 装备 / 结果级动作统一从当前选中的方案取参。选中项按内容 key 跨更新、筛选与语言保留，重排不会把你正在读的方案换成列表第一项。
- **唯一 piece 投影层**：五件护甲经过一层归一化的视图模型（含显示顺序 helmet→arms→chest→legs→classItem，以及唯一可用来取调整/模组分配的下标），消除了「排序后按下标取分配」这类错位。**待刷取的护甲同样显示求解器给出的调整与模组**，不再显示为空。
- 方案状态只在方案头部出现一次；列表只给短标记，完整说明放 `title` 与 `data-proof-label`；高级诊断默认折叠。

## UI 信息架构与响应式重构

- **结果页重建为两栏工作区**：左侧方案浏览器、右侧方案详情。
- **Plan Browser 成为有界的内容自适应 sticky 工作区**：面板高度由工具栏 + 列表 + 「显示更多」自然决定，只有列表有上限；列表上限由实测的命令栏高度与视口共同推导，因此 1024px 与 1440px 宽度下的高度预算都准确。桌面壳只覆盖该上限变量。
- **统一全应用宽度**：求解前后容器宽度与左侧位置逐像素一致，不再出现「出结果后整页变窄」。
- **信息密度**：宽屏下六维/目标输入 6 列、五件摘要 5 列、已有护甲与约束面板两列、替换路径三 lane；窄屏逐级回落到单列。
- **护甲表、刷取计划与六维格改用容器查询**，宽度由所在栏决定，而不是由视口决定。
- **命令栏高度实测**：sticky 命令栏的偏移由 ResizeObserver 实测写入，不再假设固定高度。
- **页脚简化**，方案浏览器不再保留死白空间。
- 删除了重构后失效的样式，并钉住替换路径布局，防止后续回归。

## 已有护甲、优化现有配装与替换路径

- **高级约束默认折叠**，展开后宽屏两列；套装要求汇总行把状态、徽标与套装效果开关放在一行，打开效果时占满整行。
- **五件编辑器同时只允许一件展开**，展开区字段顺序固定；摘要行在窄屏用「·」拼成一句话，宽屏变成 5 列对齐。
- **替换路径按步骤组织**：每一步给出「当前 / → 目标 / 执行」三条 lane，宽屏三列并排；长文案收进可展开区域，关键结论（状态、替换件数、保留件数、短缺量）留在首屏。
- **刷取计划只统计真正的刷取项**（含待获取的异域），已拥有件保留在混合方案里；框架统计不再把已拥有件算进去。

## Saved Builds 新交互

- **保存方案跨更新与渠道保活**：保存的方案是用户数据，不是渠道状态，因此 stable 与 develop 共用同一份已保存方案，而草稿、计算模式与 OAuth 状态仍然按渠道隔离。旧的渠道 key 只用于一次性迁移，不会被删除。
- 新增「已保存方案」抽屉：搜索、载入、重命名、删除；删除走确认 + 撤销提示；载入前会检查是否存在未保存的条件编辑。
- 方案快照失效时只提示重新求解，**绝不会删除你的方案**。

## 已知限制

- 库存重分配仍然不声称完整的否定证据或全局最优：求解器给出的局部精确分配不等于全局库存最优。
- 替换方案的「最少替换」证明只在搜索深度被完整穷尽时成立；被中断的一轮不能作为最少性结论。
- Deep 搜索仍有资源上限，未完成全域时不带穷尽证明；Fast / Balanced 的模糊搜索仍是有界的。
- 离线内联检查点无法在 JavaScript 让出执行权之前响应 DOM 事件；本版没有引入可挂起的内联求解器。
- Windows 安装包未签名，Windows 可能提示未知发布者；目标电脑需已安装 WebView2 Runtime。
