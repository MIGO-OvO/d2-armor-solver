读图说明与证明边界

基线：当前 v3.0.1 / e4909e8。采用与 V2 相同的竖向结构。四个搜索模块是替代入口，不是顺序执行；其结果汇入共同正确性边界。图中“验证”合并了各入口的 witness / proof 处理，无 witness 的不可行结论依赖独立的完整证明检查。

src/core/solver.mjs:723 与 src/core/exact-target-oracle.mjs:801：Fast 的早期种子路径、精确目标查询、K-best 后备与 Deep 模糊证明搜索。残差索引保存前五个调整坐标；第六项由总量守恒确定，并可解码具体赋值。混合调整模式按模式多重集分组枚举；固定五件及部分固定件使用专门查询。显示值 0/200 需映射到护甲值原像，不能直接当成唯一原始值。

src/core/inventory-solver.mjs:53：2+3 只用于大组合域、固定赋值和六项精确护甲点约束；索引容量不足时回退 DFS。流式节点、保留状态、完整评估与时间分别计量；调整重排仍可能有界，不能因为五件组合遍历完就宣称所有赋值穷尽。

src/core/upgrade-optimizer.mjs:1258：完整精确目标、已知调整能力、完整原像覆盖与更小替换深度搜索完整，是最少替换证明的前提。模糊后备不能作此保证。src/core/reachability.mjs 与 src/core/armor-engine.mjs：可达范围计算、点见证查找与结果证明包装。

src/core/solver-v3-contract.mjs、src/core/armor-engine.mjs:24：EXACT_TARGET_PROVEN / RULE_FEASIBLE_PROVEN / INFEASIBLE_PROVEN / SEARCH_LIMIT_REACHED；无效输入另报 INVALID_INPUT。预算耗尽不会撤销已成立的正向见证：证书仍可保留精确或可行状态，而搜索元数据记录预算终止。

src/core/search-session.mjs：同一次运行发布已验证的进度，不是每个检查点从头重跑。Deep 仍有资源上限，不能等同于保证全局穷举。证书是可执行的重建校验记录，不是密码学签名或形式化证明。

概览合并了缓存、canonical 比较器、原像枚举与各分支的辅助查询；未展开 UI、Worker 生命周期与 Bungie 写入。执行状态 VERIFIED / UNVERIFIED / BLOCKED 与数学可行性相互独立。
