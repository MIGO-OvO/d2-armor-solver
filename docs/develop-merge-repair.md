## 修复范围

- 恢复 DFS、2+3 join 的互斥分片、参数校验和分片覆盖元数据。
  当前装备也服从同一分区；单分片不得证明整个库存无解。
- 库存候选保留物理身份，只共享数学评价缓存。相同 owner、属性而不同 ID
  的五槽双副本保留全部 32 个组合。
- 自动模组、显式模组预算同时进入评价、剪枝和局部细化；Upgrade 默认仍保留
  已安装预算。固定异域装备在枚举前过滤。精确/区间 Oracle 均检查显式均衡件数。
- 保留旧 `findBestFixedConfigWitness` 能力模式下 `numPlus3` 的默认语义，
  用 `requiredNumPlus3` 传递新的显式硬约束，避免破坏旧调用方。
- 普通请求覆盖旧请求并终止 Worker；仅批次自有 Worker 并发。
  新批次或普通库存请求会取消旧批次，AbortSignal 释放计算资源。
- 分片进度中的正见证按原库存重新验证后显示，停止前已显示的结果可保留。
  分片负证据不提升成全局证明；最终结果包含聚合搜索状态。
- 同步 120 秒预算、2 百万保留状态与 5 百万评价上限的说明，修正文档中的
  重分配完整性承诺。移除 Release ZIP 上传任务，保留 Actions ZIP 工件。
- 新增 `Validate proposed changes` PR/分支校验；Windows 原生工作流也响应 PR。
  仓库管理员仍需在分支保护中把所需检查设为必需，本次未改变远端设置。

## 保留边界

- Deep 是有预算的搜索，不是无条件完全枚举。重分配模糊排名仍含有界启发式，
  不承诺全局最优；物理遍历完成也不自动证明赋值域完整。
- 并行收益随分区和数据分布变化；有限预算内不保证不同线程数取得相同候选集合。
- file:// 仍为主线程降级，不能抢占同步原语；桌面版使用 Worker。
- 构建仍有大 chunk 提示；本次未引入依赖或进行无关拆包改造。
- Windows 10/11 干净虚拟机断网安装、升级/卸载和 DPI 矩阵仍属于发布验收；
  目标机器需预装 WebView2，安装器没有签名或自动更新器。
- 本次未修改用户库存、账户、存储 schema，也未提交、推送、发布或合并分支。
