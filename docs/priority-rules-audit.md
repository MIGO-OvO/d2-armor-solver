# 优先级、属性规则与直装审查

日期：2026-09-13。本次排序仅审查，不修改算法；装备流程按需求修改。

## 结论

高/中/低优先级确实进入计算，但不是统一的“达标权重”。不同路径排序不一致，且规则内的冗余点数仍可能影响优先级评分，不能认为已经完整实现“高优先级达标比低优先级达标重要”。

### 1. 从零求解：精确总偏差可以压过高优先级

`src/core/solver.mjs` 的 `singleStatScoreRank` 输出 `[上下限违规平方和, 精确偏差平方和, 高, 中, 低, 普通]`，`compareScoreRanks` 逐字段比较。优先级不是浮点加权分，而是字段之间的严格先后顺序。

可复现实例：六项目标均100，武器高优先级、生命低优先级，其余相同且达标。

- A：武器100、生命80，排名向量 `[0,400,0,0,1200,0]`。
- B：武器90、生命100，排名向量 `[0,100,300,0,0,0]`。
- 从零评分选 B：精确总偏差100小于400，甚至还没比较高优先级字段。

### 2. 库存/升级路径：有修正，但没有统一规则语义

`src/core/upgrade-optimizer.mjs` 的 `compareUpgradeMetrics` 在整体规则达标、边界违规数及必须达标项等前置比较之后，先比较高/中/低字段，再比较精确违规数和总缺口。因此上面的同一例子会选 A。

但低优先级的上下限违规依然可以压过高优先级精确项。`src/core/inventory-solver.mjs` 还首先比较方案可行性；`src/core/inventory-plan.mjs` 先比较规则可行、已有件可行，再比较上述结构评分和刷取成本。只更改一个 UI 排序函数不能统一搜索、剪枝、候选保留与最终展示。

### 3. 达标与贴近输入值不是一回事

评分的属性拟合项使用相对输入目标的平方偏差，低于目标乘3，高于目标乘1，不随 `≤/≥/区间` 变成“距合法区间的距离”。例如高优先级生命 `≤100`：80和100都达标，但80仍被记入高优先级惩罚1200，100为0。这会在其他前置字段相同的候选之间偏向上限。

截图中的手雷135满足 `≤160`，显示达标正确；若希望至少160，应选 `≥`。武器 `=0` 且高优先级也不是忽略该属性，而是明确要求压到0。

## 建议的统一排序语义（尚未实施）

1. 物理合法性是硬条件；所有属性规则均满足的方案优先于不完全满足的方案。
2. 部分达标时，按高→中→低→无优先级比较。每层先比较未达标属性数，再比较该层规则偏差，避免较低优先级抵消较高优先级。
3. 精确规则偏差为绝对差；至少只罚不足；至多只罚超出；区间只罚越界。合法范围内偏差为0。
4. 上述字段相同，再比较刷取数量、成本及稳定的候选标识。若仍希望优先贴近区间端点，应作为最后的独立偏好，不冒充达标程度。
5. 统一修改搜索评分、下界剪枝、库存/升级比较器与展示排序，增加跨路径同一候选的差分测试。不要仅调大数权重。

“同层先比达标项数量，还是先比缺口大小”属于产品选择；这里推荐前者，因为需求强调达标的重要程度。目前代码主要比较平方偏差，不是达标数量加权。
