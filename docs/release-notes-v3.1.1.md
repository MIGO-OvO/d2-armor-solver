# v3.1.1

V3.1.1 是 v3.1.0 稳定通道上的维护版本，包含 `v3.1.0..develop` 的 5 个提交。这一轮不改动游戏规则，也不放宽求解器的证明、证书与见证校验边界，重点是**修掉几处真实使用中会遇到的可靠性问题**，并**降低大库存下的等待与内存开销**。

用户可感知的变化集中在三类：Bungie 跨存档账号识别与方案保存的可靠性、搜索状态文案与键盘操作的准确性、以及从零求解与库存加载的响应速度。

## 可靠性修复

- **Bungie 跨存档主账号识别修正**：Bungie 的 `crossSaveOverride` 字段返回的是主账号的**平台类型**（membership type），而不是账号 id。此前代码把它当作 int64 账号 id 去匹配，导致已开启跨存档的玩家可能连到错误的平台账号、读到错误的库存。现在按平台类型正确解析主账号，未开启跨存档的账号回退到首个成员，行为不变。
- **库存验证请求必须重新准备**：验证 Worker 只保留当前批次的库存，跨批次复用旧库存会被显式拒绝并报错，而不是静默地用一份过期库存去做验证。Worker 终止即释放，新批次自然取代旧批次。
- **方案保存失败不再破坏已有记录**：序列化失败（例如内容无法 JSON 化）现在会在写入之前就失败返回，不会覆盖掉上一条完好的记录。存储对象缺少 `setItem`（部分受限环境）时按「不可写」处理，不再抛异常中断流程。

## 搜索状态与键盘交互

- **补齐两种终止状态文案**：搜索被用户主动停止、以及搜索正常结束但可行性仍未证明，现在各有明确、如实的文案，不再与「达到搜索上限」或「继续搜索中」混淆。状态描述的是搜索本身，不是证明结论。
- **未找到达标解时的提示更准确**：搜索仍在进行或被停止时，不会再弹出「搜索达到限制」的误导性警告；只有真正耗尽预算才提示最佳解尚非全局最优。
- **停止搜索后的状态不再误报**：没有任何搜索结果时显示「等待开始」；已有已验证结果时提示结果已保留；否则显示尚未找到达标解。
- **方案列表支持键盘导航**：方案列表项只对当前选中项保留 Tab 焦点，并支持方向键 / Home / End 在方案之间移动，无障碍语义（`role="rowheader"` / `role="cell"`）也一并补齐。
- **编辑区重渲染后保留焦点**：配装编辑区展开/折叠导致重新渲染后，焦点会被恢复到原来的位置，不再跳回列表顶部。
- **弹层统一管理**：遮罩、Escape 关闭与焦点恢复由单一控制器负责，弹层不会互相叠加，也不会把焦点困在已关闭的层里。

## 性能与内存

- **从零求解更快收敛**：启用精确内点松弛求总量边界，在保持正确性的前提下对库存总属性做更强的剪枝；未知或超界的情形一律回退到不剪枝，不会给出错误结论。
- **证明体积压缩**：内容指纹改用同步 SHA-256 计算，在 Worker 与 `file://` 离线场景下行为一致，减少跨线程传递的证明投影体积。指纹只用于内容标识，不作为授权原语——否定证明仍需内部产出者溯源，肯定见证仍会完整重验。
- **已准备库存域复用**：引擎按引用复用同一份已准备的库存域，避免重复构建。
- **库存目录延后加载**：工作台先呈现目标与规则，库存目录按需加载，大库存打开工作台时的等待与内存占用明显降低。
- **库存模块拆分**：库存模型与传输逻辑拆分，便于按需加载与维护，行为保持不变。

## 验证与测试

- 新增/更新回归覆盖：跨存档解析（`tests/bungie-api.test.mjs`）、方案仓库持久化（`tests/build-repository.test.mjs`）、搜索生命周期、工作台交互（`scripts/verify-workbench-interaction.mjs`，已纳入 CI）、优化运行时以及库存目录契约。
- 本版所有测试、lint、构建与离线验证均通过，未放宽任何正确性断言或证明要求。

## 已知限制

与 v3.1.0 相同，未发生改变：库存重分配不声称完整的否定证据或全局最优；替换方案的「最少替换」证明仅在搜索被完整穷尽时成立；Deep 搜索仍有资源上限；Windows 安装包未签名，且目标电脑需已安装 WebView2 Runtime。
